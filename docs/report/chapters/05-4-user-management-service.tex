\subsection{مكوّنات الخدمة}

% CH2-REF: originally "(\en{Clean Architecture}) الموصوف في القسم~\ref{subsec:clean-architecture}،" — restore with chapter 2.
بُنيت الخدمة، كما بقية خدمات \en{.NET}، وفق المعمارية النظيفة (\en{Clean Architecture}) بأربع طبقات تتّجه التبعيات فيها نحو الداخل. ويعرض الشكل~\ref{fig:comp-01} مكوّنات الخدمة وروابطها الخارجية.

\begin{figure}[htbp]
  \centering
  % 1.91:1 — full width is ~35% of the text block, so it places inline.
  \includegraphics[width=\textwidth,height=0.8\textheight,keepaspectratio]{figures/comp-01-user-management.png}
  \caption{مخطط مكوّنات خدمة إدارة المستخدمين.}
  \label{fig:comp-01}
\end{figure}

وتتّصل الخدمة بمحيطها عبر ثلاثة مسارات:

\begin{enumerate}
  \item \textbf{إصدار الرموز}: تنفرد هذه الخدمة بإصدار رموز الوصول، وتكتفي بقية الخدمات بالتحقّق منها، فيبقى تعديل سياسة المصادقة في موضع واحد.
  \item \textbf{ناقل الإشعارات}: يُنشَر عليه ما يستدعي إجراءً في خدمة أخرى، كإرسال رمز المصادقة الثنائية أو الإعلام بتغيّر حالة مستخدم.
  \item \textbf{عملاء \en{HTTP} داخليون}: تستعملهم الواجهات الإدارية العابرة للخدمات، إذ يتصرّف المدير الأعلى بموارد تملكها خدمات أخرى.
\end{enumerate}

ويُستعمل الناقل هنا مباشرة لا عبر صندوق الصادر، لأن أثر الرسالة يقع في قاعدة خدمة أخرى، وهو شرط لا يستوفيه ذلك النمط.
